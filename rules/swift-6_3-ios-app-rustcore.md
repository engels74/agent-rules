# Swift 6.3 iOS App Engineering Reference

This stack builds native iOS/iPadOS apps with Swift 6.3, SwiftUI + the Observation framework for the view layer, SwiftData for persistence, Swift Testing for tests, and a Rust core exposed through UniFFI. The project is generated by XcodeGen from a `project.yml`, dependencies are resolved by SwiftPM, and style is enforced by SwiftLint. The compiler ships in Xcode 26.4 and later; the SDK is iOS 26, but the **deployment target is iOS 18** — a hard constraint. Build against the iOS 26 SDK, adopt the Swift 6 language mode, and gate every iOS 26-only API behind an availability check with a working iOS 18 fallback. A new SDK does not raise your floor.

What this stack is exceptional at: fine-grained, compiler-verified UI updates (Observation), boilerplate-free typed persistence (SwiftData), compile-time-checked data-race safety (Swift 6 concurrency), and sharing a single Rust business-logic core across platforms (UniFFI). The biggest ways agents write wrong-but-plausible code here come from importing habits from adjacent ecosystems: reaching for `ObservableObject`/`@Published`/`@StateObject` (superseded by `@Observable`/`@State`), sprinkling `DispatchQueue.main.async` and `Task.detached` instead of using actor isolation, treating SwiftData like Core Data (`NSPredicate`, manual `NSManagedObjectContext` threading) instead of `#Predicate`/`@ModelActor`, writing XCTest `XCTAssert` scaffolding instead of Swift Testing `#expect`, and passing SwiftData model objects across actor boundaries instead of their `PersistentIdentifier`. Optimize for main-actor-by-default code with deliberate, visible offloading.

## Language mode and concurrency posture

Adopt the **Swift 6 language mode** with *approachable concurrency*. The mental model: everything is `@MainActor`-isolated by default, and you move work off the main actor only where you mean to. This eliminates the flood of spurious data-race warnings that Swift 6.0 produced in ordinary UI code while keeping full compile-time race safety.

Turn this on in the package manifest (see the tooling section for the full file). The three settings that matter:

```swift
swiftSettings: [
    .defaultIsolation(MainActor.self),                       // SE-0466, SwiftPM 6.2+
    .enableUpcomingFeature("NonisolatedNonsendingByDefault"), // SE-0461
    .enableUpcomingFeature("InferIsolatedConformances"),      // SE-0470
]
```

`.defaultIsolation(MainActor.self)` is a stable `SwiftSetting` since SwiftPM tools-version 6.2; its only valid arguments are `MainActor.self` and `nil` (supplying `nil` means unannotated code is inferred `nonisolated`). Under the hood SE-0466 adds a `-default-isolation` compiler flag and the corresponding per-target `SwiftSetting`. In an XcodeGen target the equivalent build settings are `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` and `SWIFT_APPROACHABLE_CONCURRENCY: YES`, plus `SWIFT_VERSION: 6.0` for the language mode and `SWIFT_STRICT_CONCURRENCY: complete`.

Concurrency rules that are contracts, not style:

- **Never use `DispatchQueue.main.async` to "get back to the main thread."** In a main-actor-isolated context you are already there; if you are not, use `await MainActor.run { }` or mark the function `@MainActor`. `DispatchQueue` hopping defeats the isolation checker.
- **Offload CPU-bound work with `@concurrent`, not `Task.detached`.** `@concurrent` on an `async` function moves its body to the cooperative pool while preserving structured cancellation and isolation reasoning. `Task.detached` throws away the surrounding context and is almost always wrong in app code.

```swift
@concurrent
func renderThumbnail(from data: Data) async -> UIImage? {
    // Runs off the main actor on the cooperative pool.
    UIImage(data: data)?.preparingThumbnail(of: CGSize(width: 200, height: 200))
}
```

- Under SE-0461, a `nonisolated` `async` function now runs on the **caller's** actor by default, so calling it no longer forces an actor hop or a `Sendable` round-trip. Add `@concurrent` only when you specifically want to leave the caller's actor.
- Types shared across isolation domains must be `Sendable`. Prefer value types (`struct`/`enum` of `Sendable` members conform automatically) and `actor`s over `final class` + manual locking. Reach for `@unchecked Sendable` only around a documented lock, never to silence a warning.
- Structured concurrency owns its children: a `TaskGroup` cancels remaining children when the scope throws, and `async let` bindings are awaited or cancelled at scope exit. Check `Task.isCancelled` (or call `try Task.checkCancellation()`) inside long loops, and treat `CancellationError` as an ordinary expected outcome, not a failure.

```swift
func loadDashboard(ids: [UUID]) async throws -> [Panel] {
    try await withThrowingTaskGroup(of: Panel.self) { group in
        for id in ids {
            group.addTask { try await self.loadPanel(id: id) }  // child inherits cancellation
        }
        var panels: [Panel] = []
        for try await panel in group {          // throwing here cancels siblings
            panels.append(panel)
        }
        return panels
    }
}
```

## App structure, state, and the Observation framework

Model state with the `@Observable` macro on a `final class`. Do not use `ObservableObject`, `@Published`, `@StateObject`, `@ObservedObject`, or `@EnvironmentObject` — they are the pre-iOS-17 mechanism, carry a Combine dependency, and invalidate views too coarsely. `@Observable` gives SwiftUI property-level dependency tracking: a view re-renders only when a property its `body` actually read changes.

Property-wrapper selection is mechanical:

| Wrapper | Use for |
|---|---|
| `@State` | The view *owns* the `@Observable` instance (create it once here) |
| `let` / plain property | The view is *passed* an `@Observable` instance it does not own |
| `@Bindable` | You need `$model.property` bindings to a passed-in `@Observable` |
| `@Environment(MyType.self)` | Read an `@Observable` injected into the environment |

```swift
import SwiftUI
import Observation

@Observable
final class LibraryModel {
    var searchText = ""
    var isLoading = false
    private(set) var books: [Book] = []

    @ObservationIgnored private var loadTask: Task<Void, Never>?

    func refresh(using loader: BookLoader) {
        loadTask?.cancel()
        loadTask = Task {
            isLoading = true
            defer { isLoading = false }
            do { books = try await loader.fetchAll() }
            catch is CancellationError { /* superseded by a newer refresh */ }
            catch { books = [] }
        }
    }
}

struct LibraryScreen: View {
    @State private var model = LibraryModel()          // owned here
    @Environment(BookLoader.self) private var loader

    var body: some View {
        NavigationStack {
            List(model.books) { BookRow(book: $0) }
                .overlay { if model.isLoading { ProgressView() } }
                .searchable(text: $model.searchText)   // needs a binding into @State
                .navigationTitle("Library")
                .task { model.refresh(using: loader) }
        }
    }
}
```

Use `@ObservationIgnored` for stored state that must not trigger view updates (task handles, caches, injected services). Inject shared models with `.environment(model)` at a scene or container root and read them with `@Environment(LibraryModel.self)`.

For a passed-in model that a child mutates, use `@Bindable`:

```swift
struct EditBookView: View {
    @Bindable var book: Book   // an @Observable (or @Model) instance owned upstream

    var body: some View {
        Form {
            TextField("Title", text: $book.title)
            Toggle("Favorite", isOn: $book.isFavorite)
        }
    }
}
```

Combine still has a legitimate role for stream operators (debounce, throttle, merge); reach for it there, not for object observation.

### Targeting iOS 18 while building on the iOS 26 SDK

Any API introduced after iOS 18 must be gated. Wrap the modifier in a custom `ViewModifier` or a `@ViewBuilder` extension so the call site stays clean and the fallback is real, not a no-op that ships broken UI on iOS 18. The Liquid Glass APIs (`.glassEffect(_:in:)`, `GlassEffectContainer`, `.buttonStyle(.glass)`) are iOS 26-only.

```swift
extension View {
    @ViewBuilder
    func cardGlass(in shape: some Shape = .rect(cornerRadius: 16)) -> some View {
        if #available(iOS 26.0, *) {
            glassEffect(.regular, in: shape)
        } else {
            background(.ultraThinMaterial, in: shape)      // real iOS 18 fallback
                .overlay(shape.stroke(.white.opacity(0.15), lineWidth: 1))
        }
    }
}
```

Put `@available(iOS 26.0, *)` on any helper `View`/type that stores an iOS 26-only type, and select it with `if #available` — an availability guard on a stored `@Environment`/property type must live on the containing type. Code that supports iOS 18 behind a check is current code, not legacy.

## Data layer: SwiftData

Define models with the `@Model` macro on a `final class`. `@Model` synthesizes persistence and makes the class observable, so SwiftData models work directly with SwiftUI's `@State`, `@Bindable`, and `@Query`.

```swift
import SwiftData

@Model
final class Book {
    #Unique<Book>([\.isbn])                 // uniqueness constraint
    #Index<Book>([\.title], [\.addedAt])    // query indexes

    var title: String
    var isbn: String
    var addedAt: Date
    var isFavorite: Bool = false

    @Relationship(deleteRule: .cascade, inverse: \Review.book)
    var reviews: [Review] = []

    init(title: String, isbn: String, addedAt: Date = .now) {
        self.title = title
        self.isbn = isbn
        self.addedAt = addedAt
    }
}
```

Always set an explicit `deleteRule` and `inverse` on relationships; leaving them implicit is the most common source of orphaned rows and surprise deletions. Use `@Attribute(.externalStorage)` for large blobs and `@Attribute(.unique)` (or the `#Unique` macro) for natural keys.

### Container and context

Create one `ModelContainer` for the app and inject it into the environment; SwiftUI derives the main-thread `mainContext` from it.

```swift
@main
struct BookshelfApp: App {
    let container: ModelContainer

    init() {
        do {
            container = try ModelContainer(
                for: Book.self, Review.self,
                configurations: ModelConfiguration()   // on-disk, default location
            )
        } catch {
            fatalError("Could not create ModelContainer: \(error)")
        }
    }

    var body: some Scene {
        WindowGroup { RootView() }
            .modelContainer(container)
    }
}
```

### Querying with @Query

`@Query` reads models in a view and re-runs automatically when the store changes. Filter with the `#Predicate` macro (compile-time typed, unlike `NSPredicate`) and sort with key paths or `SortDescriptor`.

```swift
struct FavoritesList: View {
    @Query(
        filter: #Predicate<Book> { $0.isFavorite },
        sort: \Book.addedAt, order: .reverse
    )
    private var favorites: [Book]

    var body: some View { List(favorites) { BookRow(book: $0) } }
}
```

For a filter that depends on runtime input, build the `@Query` in the view's `init` from a `FetchDescriptor`. Note `#Predicate` cannot capture `Date.now` directly — bind a local first.

```swift
struct BookSearchList: View {
    @Query private var books: [Book]

    init(searchText: String) {
        let predicate = #Predicate<Book> { book in
            searchText.isEmpty || book.title.localizedStandardContains(searchText)
        }
        _books = Query(filter: predicate, sort: \Book.title)
    }

    var body: some View { List(books) { BookRow(book: $0) } }
}
```

For fetches outside a view (services, background work), use `FetchDescriptor` and set `fetchLimit`, `propertiesToFetch`, and indexes to keep queries cheap; use `context.fetchCount(_:)` when you only need a count.

### Background work with @ModelActor

`ModelContext` is not `Sendable` and is bound to the actor that created it. For imports, syncs, and batch writes, use a dedicated `@ModelActor`, which synthesizes an actor owning its own context on a background executor. **Never pass a `@Model` instance across the actor boundary — pass its `PersistentIdentifier` and re-fetch inside the actor.**

```swift
@ModelActor
actor ImportActor {
    func importBooks(_ payloads: [BookPayload]) throws {
        for payload in payloads {
            modelContext.insert(Book(title: payload.title, isbn: payload.isbn))
        }
        try modelContext.save()   // batch save once, not per row
    }

    func title(for id: PersistentIdentifier) -> String? {
        let book = modelContext.model(for: id) as? Book
        return book?.title
    }
}

// Call site (from the main actor):
let importer = ImportActor(modelContainer: container)
try await importer.importBooks(payloads)
```

### Schema versioning and migration

Prefer automatic lightweight migration: adding a property with an inline default (`var isFavorite: Bool = false`) or a new model requires **no** `VersionedSchema` or `MigrationPlan`. Introduce a `VersionedSchema` + `SchemaMigrationPlan` only when a change cannot be lightweight — a data transformation, a model split, or a rename requiring custom logic. When you do, wrap each version's models in an `enum: VersionedSchema` with a `versionIdentifier`, and describe transitions with `.custom(...)` (using `willMigrate`/`didMigrate`) or `.lightweight` stages.

```swift
enum SchemaV1: VersionedSchema {
    static var versionIdentifier = Schema.Version(1, 0, 0)
    static var models: [any PersistentModel.Type] { [Book.self, Review.self] }
}

enum SchemaV2: VersionedSchema {
    static var versionIdentifier = Schema.Version(2, 0, 0)
    static var models: [any PersistentModel.Type] { [Book.self, Review.self] }
}

enum BookshelfMigrationPlan: SchemaMigrationPlan {
    static var schemas: [any VersionedSchema.Type] { [SchemaV1.self, SchemaV2.self] }
    static var stages: [MigrationStage] {
        [.custom(
            fromVersion: SchemaV1.self, toVersion: SchemaV2.self,
            willMigrate: { context in /* dedupe before the unique constraint applies */ },
            didMigrate: nil
        )]
    }
}
```

Pass the plan when constructing the container: `try ModelContainer(for: Book.self, migrationPlan: BookshelfMigrationPlan.self, configurations: ModelConfiguration())`. A failed migration throws out of the initializer — the container fails to open, and handling that (recovery UI, restore, or fresh store) is the app's responsibility; SwiftData does not silently discard user data.

## Rust core over UniFFI

The business-logic core is a Rust crate exposed to Swift by **UniFFI**. Use the proc-macro API (`#[uniffi::export]`, `#[derive(uniffi::Record)]`, `#[derive(uniffi::Enum)]`, `#[derive(uniffi::Object)]`) rather than the UDL file — proc-macros keep the interface next to the implementation and are the maintained default. Call `uniffi::setup_scaffolding!()` once at the crate top level.

```rust
// lib.rs
uniffi::setup_scaffolding!();

#[derive(uniffi::Record)]
pub struct Suggestion {
    pub title: String,
    pub score: f64,
}

#[derive(uniffi::Enum)]
pub enum RankMode { Recent, Popular }

#[derive(Debug, thiserror::Error, uniffi::Error)]
pub enum EngineError {
    #[error("no data available")]
    Empty,
    #[error("invalid query: {reason}")]
    InvalidQuery { reason: String },
}

#[derive(uniffi::Object)]
pub struct Recommender { /* private state */ }

#[uniffi::export]
impl Recommender {
    #[uniffi::constructor]
    pub fn new() -> Self { Self { /* ... */ } }

    pub fn rank(&self, query: String, mode: RankMode) -> Result<Vec<Suggestion>, EngineError> {
        if query.is_empty() { return Err(EngineError::InvalidQuery { reason: "empty".into() }); }
        Ok(vec![])
    }
}
```

On the Swift side this generates a `Recommender` class, a `Suggestion` struct, a `RankMode` enum, and an `EngineError: Error` enum, so the boundary maps onto idiomatic Swift `throws`:

```swift
import RecommenderCore

let engine = Recommender()
do {
    let results = try engine.rank(query: text, mode: .popular)
} catch let error as EngineError {
    // handle Empty / InvalidQuery
}
```

Cross-boundary contracts to respect:

- **Errors:** return `Result<T, E>` from Rust where `E: uniffi::Error`; it surfaces as a Swift `throws`. Map Rust panics out — a panic aborts, it does not become a Swift error.
- **Async:** UniFFI supports `async fn`, surfaced as Swift `async`. Annotate the export with the runtime, e.g. `#[uniffi::export(async_runtime = "tokio")]`, when methods `.await` on a Tokio runtime. UniFFI's own docs describe Swift 6 support as partial: most generated code conforms to `Sendable`, but async generated code is known not to conform yet (tracked in issue #2448) — so keep calls into async Rust on a defined actor.
- **Cancellation is not automatic:** UniFFI provides no built-in way to cancel a future or raise a native `CancellationError`, and dropping a Swift `Task` does not cancel in-flight Rust work. Expose an explicit `cancel()`/flag on the Rust side and map it to an error or empty result if you need cooperative cancellation.

### Packaging as an XCFramework in a SwiftPM binary target

Ship the compiled Rust as an `.xcframework` consumed through a SwiftPM `binaryTarget`, with the generated Swift bindings in a sibling source target that depends on it. Build for `aarch64-apple-ios` (device), `aarch64-apple-ios-sim` and `x86_64-apple-ios` (simulator, `lipo`'d together), generate bindings with `uniffi-bindgen-swift` — which always runs in library mode and therefore always supports proc-macro-based generation — assemble with `xcodebuild -create-xcframework`, and record the archive checksum in `Package.swift` when hosting the zip.

```swift
// swift-tools-version: 6.2
import PackageDescription

let package = Package(
    name: "RecommenderCore",
    platforms: [.iOS(.v18)],
    products: [
        .library(name: "RecommenderCore", targets: ["RecommenderCore"]),
    ],
    targets: [
        .binaryTarget(
            name: "RecommenderFFI",
            path: "artifacts/RecommenderFFI.xcframework"   // or url:/checksum: when hosted
        ),
        .target(
            name: "RecommenderCore",
            dependencies: ["RecommenderFFI"],
            path: "Sources/RecommenderCore",               // generated .swift bindings live here
            swiftSettings: [.defaultIsolation(MainActor.self)]
        ),
    ],
    swiftLanguageModes: [.v6]
)
```

A representative binding-generation step:

```bash
cargo build --release --target aarch64-apple-ios
cargo run --bin uniffi-bindgen-swift -- \
    target/aarch64-apple-ios/release/librecommender.a build/swift \
    --swift-sources --headers --modulemap
```

Regenerate bindings and rebuild the XCFramework whenever the Rust interface changes; wire this into a shell script and CI so the binary artifact never drifts from the source. Pin the `uniffi` crate and the `uniffi-bindgen` CLI to the **same** version — a mismatch produces bindings that fail at load with contract-version errors.

## Project generation with XcodeGen

The `.xcodeproj` is generated from `project.yml`; keep the project file out of git and run `xcodegen generate` before opening or building. Declare SwiftPM dependencies under `packages`, reference them per target under `dependencies` with `package:`/`product:`, and set the deployment target and concurrency build settings in `settings`.

```yaml
name: Bookshelf
options:
  bundleIdPrefix: com.example
  deploymentTarget:
    iOS: "18.0"
packages:
  RecommenderCore:
    path: RustCore/RecommenderCore     # local SwiftPM package wrapping the XCFramework
  SwiftLintPlugins:
    url: https://github.com/SimplyDanny/SwiftLintPlugins
    exact: 0.63.2
settings:
  base:
    SWIFT_VERSION: "6.0"                # Swift 6 language mode
    SWIFT_STRICT_CONCURRENCY: complete
    SWIFT_APPROACHABLE_CONCURRENCY: YES
    SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor
    IPHONEOS_DEPLOYMENT_TARGET: "18.0"
targets:
  Bookshelf:
    type: application
    platform: iOS
    sources: [Sources/Bookshelf]
    dependencies:
      - package: RecommenderCore
        product: RecommenderCore
    buildToolPlugins:
      - plugin: SwiftLintBuildToolPlugin
        package: SwiftLintPlugins
    scheme:
      testTargets:
        - BookshelfTests
        - BookshelfUITests
  BookshelfTests:
    type: bundle.unit-test
    platform: iOS
    sources: [Tests/BookshelfTests]
    dependencies:
      - target: Bookshelf
  BookshelfUITests:
    type: bundle.ui-testing
    platform: iOS
    sources: [Tests/BookshelfUITests]
    dependencies:
      - target: Bookshelf
```

`SWIFT_VERSION: "6.0"` selects the Swift 6 *language mode*, independent of the 6.3 toolchain. Because SwiftPM packages do not get MainActor default isolation implicitly, set `.defaultIsolation(MainActor.self)` in each local package's manifest as well as the app target's build settings.

## Testing with Swift Testing

Write unit and logic tests with **Swift Testing** (`import Testing`): `@Test` functions, `@Suite` types, `#expect` for soft assertions, and `#require` for preconditions that stop the test when they fail. Do not write new XCTest `XCTAssert*` code. XCTest remains only for **UI automation** (`XCUIApplication`) and performance tests (`XCTMetric`), which Swift Testing does not cover; the two run side by side in the same target.

```swift
import Testing
@testable import Bookshelf

@Suite("Ranking")
struct RankingTests {
    @Test("Empty query is rejected")
    func emptyQueryThrows() {
        let engine = Recommender()
        #expect(throws: EngineError.self) {
            try engine.rank(query: "", mode: .recent)
        }
    }

    @Test("Scores stay within bounds", arguments: ["swift", "rust", "ios"])
    func scoresBounded(term: String) throws {
        let results = try Recommender().rank(query: term, mode: .popular)
        for r in results { #expect((0.0...1.0).contains(r.score)) }
    }
}
```

Key behaviours:

- **Parameterized tests** via `@Test(arguments:)` produce one child result per argument and run in parallel; two argument collections form the cross-product, so use `zip(a, b)` for paired inputs. Failures name the offending argument, so you rarely need to isolate a case.
- **Parallel by default.** Tests run concurrently via Swift Concurrency. When a suite shares mutable external state (a real database, a file), apply `.serialized` to the `@Suite` to force sequential execution; it is inherited by nested suites.
- **Traits** configure behaviour: `.tags(.network)`, `.enabled(if:)`, `.disabled("reason")`, `.timeLimit(.minutes(1))`, `.bug("FB12345")`. Define tags in an `extension Tag`. Swift 6.3 additionally allows recording a non-failing warning issue with `Issue.record("…", severity: .warning)` and cancelling a running test with `try Test.cancel()`.
- **Async is native** — mark the test `async throws` and `await` directly; no expectation/waiter ceremony.

### Testing SwiftData and main-actor code

Use an in-memory container so tests are isolated and need no cleanup. Test your logic (stores, computed aggregates), not that SwiftData can insert and fetch. Isolate the test to `@MainActor` when it touches `mainContext`.

```swift
import Testing
import SwiftData
@testable import Bookshelf

@MainActor
@Test("Favorites count reflects inserts")
func favoritesCount() throws {
    let container = try ModelContainer(
        for: Book.self, Review.self,
        configurations: ModelConfiguration(isStoredInMemoryOnly: true)
    )
    let context = container.mainContext
    context.insert(Book(title: "A", isbn: "1"))
    let fav = Book(title: "B", isbn: "2"); fav.isFavorite = true
    context.insert(fav)
    try context.save()

    let count = try context.fetchCount(
        FetchDescriptor<Book>(predicate: #Predicate { $0.isFavorite })
    )
    #expect(count == 1)
}
```

Hold the `ModelContainer` for the duration of the test: if you grab `container.mainContext` and let the container go out of scope, the context's container reference becomes invalid and inserts crash. Keep the container in a `let` that lives across the assertions (or build container and context per test).

## Linting and formatting

Run **SwiftLint** as a SwiftPM **build tool plugin** so violations surface inline on every build, and consume it from the dedicated **`SimplyDanny/SwiftLintPlugins`** package rather than `realm/SwiftLint`. The dedicated package ships SwiftLint as a prebuilt binary, so it does not drag in a SwiftSyntax build and cannot create a SwiftSyntax version conflict with your macros. Pin an exact version — `0.63.2` is the current release.

```swift
// In the app's SwiftPM package, or via XcodeGen buildToolPlugins as shown above.
.package(url: "https://github.com/SimplyDanny/SwiftLintPlugins", exact: "0.63.2")
// target:
plugins: [ .plugin(name: "SwiftLintBuildToolPlugin", package: "SwiftLintPlugins") ]
```

Place a `.swiftlint.yml` at the repo root (the plugin resolves its working directory from the topmost config):

```yaml
opt_in_rules:
  - empty_count
  - first_where
  - toggle_bool
  - explicit_init
disabled_rules:
  - todo
excluded:
  - .build
  - Sources/RecommenderCore   # generated UniFFI bindings
identifier_name:
  min_length:
    warning: 2
  excluded: [id, url, x, y]
line_length:
  warning: 120
  error: 200
```

For formatting, use **swift-format** — it ships inside the Swift toolchain (invoke via `xcrun swift-format` or `swift format`) and is the maintained Apple-official formatter for this toolchain. Add a `.swift-format` JSON config at the repo root and run `swift-format format --in-place --recursive Sources Tests` in a pre-commit hook or CI step. SwiftLint enforces conventions; swift-format owns whitespace and layout — keep their responsibilities separate rather than using SwiftLint's autocorrect as a formatter.

Common commands for the whole setup:

```bash
xcodegen generate                                   # regenerate the .xcodeproj
xcodebuild -scheme Bookshelf -destination 'platform=iOS Simulator,name=iPhone 16' build
xcodebuild test -scheme Bookshelf -destination 'platform=iOS Simulator,name=iPhone 16'
swift-format format --in-place --recursive Sources Tests
```

## Anti-patterns to avoid

| Wrong | Why | Right |
|---|---|---|
| `class VM: ObservableObject { @Published var x }` | Pre-iOS-17 mechanism; Combine dependency; coarse invalidation | `@Observable final class VM { var x }` with `@State`/`@Bindable` |
| `@StateObject`/`@ObservedObject`/`@EnvironmentObject` | Paired with `ObservableObject`, superseded | `@State` (owned), `let` (passed), `@Environment(T.self)` (injected) |
| `DispatchQueue.main.async { … }` in UI code | Defeats actor isolation; already on `@MainActor` | Rely on default MainActor isolation, or `await MainActor.run { }` |
| `Task.detached { heavyWork() }` | Discards isolation and cancellation context | `@concurrent func heavyWork() async` |
| `NSPredicate(format:)` for SwiftData | Untyped, runtime-checked; Core Data habit | `#Predicate<T> { … }` (compile-time typed) |
| Passing a `@Model` object into a `@ModelActor` | `ModelContext`/models aren't `Sendable` across actors | Pass `PersistentIdentifier`, re-fetch inside the actor |
| Creating a `VersionedSchema`/`MigrationPlan` to add a defaulted field | Unnecessary; lightweight migration handles it | Add `var flag: Bool = false`; no plan needed |
| iOS 26 API (`glassEffect`) called unguarded | Crashes / fails to build for the iOS 18 target | Gate with `if #available(iOS 26.0, *)` + real fallback |
| `XCTAssertEqual` in new tests | XCTest is legacy for logic tests | `#expect(...)` / `#require(...)` in Swift Testing |
| UDL `.udl` file for a new UniFFI interface | Extra artifact to keep in sync | Proc-macros (`#[uniffi::export]`, `#[derive(uniffi::Record)]`) |
| `realm/SwiftLint` as SPM plugin | Pulls a SwiftSyntax build; version conflicts with macros | `SimplyDanny/SwiftLintPlugins` (prebuilt binary), pinned |
| Letting `ModelContainer` go out of scope after grabbing `mainContext` | Context's container reference goes invalid; inserts crash | Keep the container alive across the test |
